# AWS Source Connection Technical Reference

Technical reference for configuring **SailPoint Fabric** (AWS SaaS connector) and **CIEM AWS** sources via `Connect-SailPointAWS` and `AWS.ps1`.

---

## 1. Overview & Source Types

`AWS.ps1` and `Connect-SailPointAWS` support two distinct SailPoint ISC sources. Configure **one per run** (`-SourceType AwsSaas` or `-SourceType CiemAws`). Each type writes to a different default directory and settings file:

| Source Type | Default Output Directory | Settings File |
| :--- | :--- | :--- |
| `AwsSaas` (default) | `~/.sailpoint-connect/<project>/AWS/Amazon-Web-Services-SaaS/` | `sailpoint-aws-connection-settings.txt` |
| `CiemAws` | `~/.sailpoint-connect/<project>/AWS/Amazon-Web-Services-CIEM/` | `sailpoint-ciem-aws-connection-settings.txt` |

> [!IMPORTANT]
> The SaaS source governs **IAM** users, roles, and groups. **Identity Center** (formerly AWS SSO) users and permission sets are governed by a **CIEM AWS** source (`-SourceType CiemAws`), so SaaS options do not grant `sso:` or `identitystore:` permissions. Do not enable CIEM on the SaaS source if you already run a dedicated CIEM AWS source on the same management account.

---

## 2. AWS SaaS Connector (IAM Role Trust)

The Amazon Web Services SaaS connector authenticates via **IAM Role** assumption: SailPoint assumes a role in your management account (and a role of the same name in each member account) using an External ID from the ISC Connection Settings.

### Prerequisites

- PowerShell 7+ (`pwsh`)
- AWS CLI or AWS Tools for PowerShell (`AWS.Tools.SecurityToken`, `AWS.Tools.IdentityManagement`, `AWS.Tools.Organizations`)
- For `-Feature Ciem`: `AWS.Tools.CloudTrail`, `AWS.Tools.EC2`, and the CloudTrail log S3 bucket
- The **External ID** generated by ISC in the source Connection Settings
- For organization-wide deployment: `organizations:ListAccounts` plus a member-account role the caller can assume (e.g., `OrganizationAccountAccessRole`)

### Parameterized Usage

```powershell
# Single account SaaS setup with CIEM and Activity Insights
Connect-SailPointAWS `
  -ProfileName 'AdministratorAccess' `
  -ExternalId '11111111-2222-3333-4444-555555555555' `
  -RoleName 'SailPointAWSRole' `
  -Feature ActivityInsights,Ciem `
  -CloudTrailBucket 'my-org-cloudtrail-logs' `
  -Action Run

# Organization-wide SaaS setup with AI Agent Discovery
Connect-SailPointAWS `
  -ExternalId '11111111-2222-3333-4444-555555555555' `
  -Scope Organization `
  -MemberAssumeRole 'OrganizationAccountAccessRole' `
  -Feature AgentDiscovery `
  -Action BuildScript
```

### Trust Principals

The role trust policy grants `sts:AssumeRole` conditioned on `sts:ExternalId` matching the ISC External ID:

| Cloud | Label | Trusted Principal |
| :--- | :--- | :--- |
| **Commercial** | CIEM (documented) | `arn:aws:iam::874540850173:role/ciem_universal` |
| **Commercial** | ISC SaaS (runtime) | `arn:aws:iam::706944607044:role/ciem_universal` |
| **GovCloud** | Documented | `arn:aws-us-gov:iam::229634586956:role/ciem_universal` |

Commercial runs automatically trust both `874540850173` and `706944607044`. Pass `-TrustPrincipal` to specify alternative accounts.

### Policy Sets & Feature Packs

#### Required Policies
- `SPAggregationPolicy`: Read IAM users, groups, roles, policies, tags, and credentials.
- `SPOrganizationPolicy`: Read organization accounts, OUs, SCPs, and tags.
- `SPProvisioningPolicy`: Create, update, and delete users and entitlements (omitted when `-Access ReadOnly` or `-AggregationOnly`).

#### Optional Feature Packs (`-Feature`)
- `ActivityInsights`: Attaches `SPActivityInsightsPolicy` (`cloudtrail:LookupEvents`, `cloudtrail:List*`) and adds `sts:TagSession` to the role trust.
- `Ciem`: Attaches `SPCiemPolicy` and grants access to the CloudTrail S3 bucket.
- `AgentDiscovery`: Attaches `SPAgentDiscoveryPolicy` for **SailPoint Agentic Fabric**:
  - **Bedrock Agents**: `bedrock:ListAgents`, `bedrock:GetAgent`, `bedrock:ListKnowledgeBases`, `kms:Decrypt`, `kms:GenerateDataKey`.
  - **Bedrock AgentCore**: `bedrock-agentcore:ListAgentRuntimes`, `bedrock-agentcore:GetGateway`, `bedrock-agentcore:ListWorkloadIdentities`.
  - **Connect & Lex**: `connect:ListBots`, `connect:DescribeInstance`, `lex:ListBots`, `lex:GetBot`.

## 3. CIEM AWS Source (CloudFormation)

The dedicated CIEM AWS source deploys SailPoint's published CloudFormation templates for StackSets (organization inventory) and management-account activity trails.

### Collection Modes

| Scope | Mode | CloudFormation Template (Commercial) |
| :--- | :--- | :--- |
| Organization | Inventory | `commercial-inventory-collection.json` (StackSet) |
| Organization | Activity | `commercial-activity-collection.json` (Management account stack) |
| Single account | Inventory only | `commercial-inventory-collection.json` (Stack) |
| Single account | Existing CloudTrail + Bucket | `commercial-activity-collection-existing-cloudtrail.json` |
| Single account | New Trail + Existing Bucket | `commercial-activity-collection-new-cloudtrail-and-existing-bucket.json` |
| Single account | New Trail + New Bucket | `commercial-activity-collection-new-cloudtrail-and-bucket.json` |

### Parameterized CIEM Deployment

```powershell
Connect-SailPointAWS `
  -SourceType CiemAws `
  -ExternalId '11111111-2222-3333-4444-555555555555' `
  -CloudTrailBucket 'my-org-cloudtrail-logs' `
  -Scope Organization `
  -CiemActivity OrganizationManagement `
  -Action Run
```

### Identity Center Integration

- **Single Account (Account instance):** Identity Center is mutually exclusive with single-account CIEM mode.
- **Organization Scope:** The script configures `EnableIdentityStoreReadOnly` and `EnableIdentityStoreProvision` (default: true).

## 4. ISC Connection Settings Mapping

| Script Output | ISC Connection Settings Field |
| :--- | :--- |
| **Role Name** (SaaS) | Role Name (**name only**, e.g., `SailPointAWSRole`, not the ARN) |
| **Role ARN** (CIEM) | Role ARN |
| **Region** | Region (STS / Organizations endpoint) |
| **External ID** | External ID (matching the ISC-generated string) |
| **Management Account ID** | Management Account ID (12-digit AWS root account ID) |
| **AWS Accounts** | AWS Account Settings → AWS Accounts (Cloud Scope) |
| **CloudTrail ARN(s)** | CloudTrail ARN in CIEM Settings (up to 150 comma-separated ARNs) |
| **CloudTrail Bucket Account ID**| AWS CloudTrail Bucket Account ID |

## 5. Troubleshooting Guide

| Symptom | Cause and Fix |
| :--- | :--- |
| `AWS authentication failed` | Run `aws login`, `aws sso login`, or `aws configure`, then pass `-ProfileName`. |
| `Assembly with same name is already loaded` | SDK assemblies from different AWS.Tools versions loaded in one session. Restart `pwsh` and re-run. |
| `Failed to get config options for key: cloudScope` / AWS Accounts dropdown empty | ISC lists accounts by assuming the role in the **management (root)** account. Ensure `SailPointAWSRole` is deployed in the management account with `organizations:ListAccounts`. |
| `AWSOrganizationsNotInUseException` | The account is standalone. SailPoint requires an organization for AWS SaaS. Run `aws organizations create-organization` or join one. |
| Test connection fails with assume-role / External ID | Ensure the trust policy includes both SailPoint commercial trust accounts (`874540850173` and `706944607044`) and the External ID exactly matches. |
