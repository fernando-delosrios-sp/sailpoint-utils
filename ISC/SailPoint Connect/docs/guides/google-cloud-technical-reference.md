# Google Cloud & Workspace Technical Reference

Technical reference for configuring **SailPoint Fabric** (Google Workspace SaaS connector), **GCP CIEM**, and **Entro** integrations via `Connect-SailPointGoogleCloud` and `Google Cloud.ps1`.

---

## 1. Overview & Authentication Models

The Google Workspace SaaS connector supports two primary grant types:

| Grant Type | Connection Settings Fields | Best Used When |
| :--- | :--- | :--- |
| **Service Account** (Recommended) | Service Account Email, Impersonate User Email, Scopes, Private Key, Private Key Password | Standard enterprise setup; required for GCP CIEM and NHI Discovery |
| **Client Credentials** | Client ID, Client Secret, Refresh Token | Interactive OAuth sign-in flow by an admin user |

---

## 2. Prerequisites

- PowerShell 7+ (`pwsh`)
- [Google Cloud SDK](https://cloud.google.com/sdk/docs/install) (`gcloud`) authenticated with permission to manage IAM, service accounts, and projects
- [OpenSSL](https://www.openssl.org/) on PATH (or built-in LibreSSL on macOS) for generating the encrypted RSA PEM required by SailPoint ISC
- For Service Account: An existing Google Workspace Super Admin or delegated administrator to impersonate

---

## 3. Scopes & Permissions

### Core Scopes (Always Requested)
- `https://www.googleapis.com/auth/admin.directory.group`
- `https://www.googleapis.com/auth/admin.directory.user`
- `https://www.googleapis.com/auth/apps.groups.settings`
- `https://www.googleapis.com/auth/admin.directory.rolemanagement`
- `https://www.googleapis.com/auth/admin.directory.rolemanagement.readonly`

### Optional Feature Packs (`-Feature`)

| Feature Pack | Enabled APIs / Scopes / Roles | Purpose |
| :--- | :--- | :--- |
| `Gcp` | Cloud Resource Manager, Cloud Asset, IAM; custom org role `sailpointGoogleWorkspace` | GCP organization asset and IAM governance |
| `Ciem` | Cloud Asset search and IAM get permissions | Google Cloud CIEM posture analysis |
| `GmailDelegates` | Gmail API + `gmail.settings.sharing`, `gmail.settings.basic` | Governance of delegated Gmail mailboxes |
| `DeltaAggregation` | `admin.reports.audit.readonly` | Incremental change aggregation |
| `ActivityInsights` | `admin.reports.audit.readonly`, `admin.reports.usage.readonly` | User activity and license usage tracking |
| `DomainManagement` | `admin.directory.domain` | Multi-domain Google Workspace management |
| `AgentDiscovery` | `aiplatform.googleapis.com`, `aiplatform.agents.get`, `aiplatform.agents.list` | Discovery of Google Vertex AI reasoning engines and agents |

## 4. Domain-Wide Delegation Walkthrough

Google requires a manual step in the Admin Console to authorize domain-wide delegation:

1. Open [Google Admin Console → Security → API Controls → Domain-wide Delegation](https://admin.google.com/ac/owl/domainwidedelegation).
2. Click **Add new**.
3. In **Client ID**, paste the numeric Client ID generated by the tool.
4. In **OAuth Scopes**, paste the comma-separated scopes provided in `sailpoint-gws-domain-wide-delegation.txt`.
5. Click **Authorize**.

## 5. Parameterized CLI Examples

```powershell
# Headless Service Account configuration with GCP CIEM
Connect-SailPointGoogleCloud `
  -ProjectId 'sailpoint-gws-sec' `
  -ImpersonateUser 'admin@company.com' `
  -Feature Gcp,Ciem `
  -Action Run

# Generate offline requirements checklist for platform team
Connect-SailPointGoogleCloud `
  -ProjectId 'sailpoint-gws-sec' `
  -OrganizationId '123456789012' `
  -Feature AgentDiscovery `
  -Action BuildRequirements
```

## 6. Troubleshooting

| Symptom | Cause and Fix |
| :--- | :--- |
| `gcloud was not found on PATH` | Install the Google Cloud SDK and ensure `gcloud` is available in your shell PATH. |
| Test connection fails with `unauthorized_client` / `invalid_grant` | Domain-wide delegation was not configured in Google Admin, uses the email instead of numeric client ID, or has a mismatched scope list. |
| ISC rejects the private key | Ensure you paste the **encrypted RSA PEM** (`sailpoint-gws-rsa.pem`), not the Google JSON key file. |
| `403 InsufficientPermission` on GCP datasets | The organization custom role must be bound to **both** the service account and the impersonated user. Re-run with `Connect-SailPointGoogleCloud` to ensure dual binding. |
| Agent Discovery finds no agents | Vertex AI Agents must run in the specified regions. Ensure the regions listed in ISC match the active deployment regions. |
