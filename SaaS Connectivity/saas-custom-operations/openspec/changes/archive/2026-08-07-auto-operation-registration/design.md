## Context

`operation-schema-codegen` eliminated manual `defineOperationSchema` maps by generating `*.schema.ts` sidecars from `OperationSignature.output`. Authors still register commands manually in `index.ts`, declare commands in `connector-spec.json`, and import sidecars for auto ops.

Exploration validated build-time discovery from an optional `command` string literal on `OperationSignature`, extending the existing TypeScript AST parser in `operation-introspection.ts`.

## Goals / Non-Goals

**Goals:**

- Optional `command?: string` on base `OperationSignature`
- Auto-discover ops with `command` literal + exactly one `customOperation` export per file
- Generate `auto-registry.ts` for handler registration and schema registration at module load
- Schema registry fallback in `customOperation` when `operationSchema` omitted (auto ops)
- Sync `connector-spec.json` `commands[]` from discovered ops (auto + manual)
- Fail build on duplicates, invalid command prefix, 0/2+ exports per auto file
- Preserve manual registration path for ops without `command` (explicit `operationSchema` required)
- Unified discovery for templates generator

**Non-Goals:**

- Runtime interface parsing
- Schema auto-wiring for manual ops
- Multiple ops per file
- Non-literal command values
- Manifest-only (unimplemented) commands

## Decisions

### D1: Discovery source

- **Choice:** Scan `src/operations/*.ts`; exclude `_template.ts`, `index.ts`, `*.schema.ts`, `auto-registry.ts`
- **Auto op criteria:** `OperationSignature` interface with `command` string literal + exactly one `export const … = customOperation<…>(`
- **Manual op criteria:** Registered via `index.ts` `.command('custom:…', handler)` where handler module has no `command` on interface
- **Unified API:** `discoverAllOperations(operationsDir, indexPath)` returns auto + manual; validates collisions

### D2: Generated auto-registry.ts

```typescript
/** AUTO-GENERATED by npm run codegen:schemas — do not edit manually */
import { Connector } from '@sailpoint/connector-sdk'
import { exampleOperation } from './example-operation'
import { exampleOperationSchema } from './example-operation.schema'
import { registerOperationSchema } from '../framework'

registerOperationSchema('custom:example', exampleOperationSchema)

export function registerAutoOperations(connector: Connector): Connector {
    return connector.command('custom:example', exampleOperation)
}
```

- **Choice:** Committed generated file; prebuild regen
- **`registerCommands`:** calls `registerAutoOperations(connector)` then manual `.command()` lines

### D3: Schema registry (auto ops only)

- **Choice:** `Map<string, OperationSchemaContract>` in `operation-schema-registry.ts`
- **`customOperation`:** `deps.operationSchema ?? getOperationSchema(context.commandType)`
- **Manual ops:** unchanged — must pass `{ operationSchema: sidecar }`

### D4: connector-spec.json sync

- **Choice:** Read existing JSON; replace `commands` with sorted union of all discovered commands; preserve all other keys
- **Validation:** `command` must start with `custom:`

### D5: Codegen scope expansion

- **Choice:** Extend `generate-operation-schemas.ts` (keep npm script name `codegen:schemas` for compatibility)
- **Outputs per build:** sidecars (all ops), `auto-registry.ts`, updated `connector-spec.json`

### D6: Collision and export rules

- **Choice:** Exit 1 when:
  - Same command in auto-discovery and manual index
  - Duplicate command across auto modules
  - Auto module with `command` but 0 or 2+ `customOperation` exports
  - `command` not a string literal or not `custom:*` prefix

### D7: Templates alignment

- **Choice:** `loadOperationMeta` uses `discoverAllOperations` instead of `parseRegistrations` alone
- **Remove:** Scenario expecting manifest-only unregistered commands in templates output

## Risks / Trade-offs

- [Risk] Codegen overwrites connector-spec.json → Mitigation: only mutate `commands[]`; review in PR
- [Risk] Author adds `command` but forgets rebuild → Mitigation: prebuild; committed generated files show diff
- [Trade-off] Manual ops still need sidecar import → Accepted per user decision (auto-only schema registry)
