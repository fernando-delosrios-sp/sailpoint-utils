## Context

`dynamic-result-source` added runtime schema reconciliation driven by `operationSchema.outputFields`. Authors supply those fields via `defineOperationSchema(...)`, duplicating the `OperationSignature.output` interface.

`scripts/templates/operation-introspection.ts` already extracts output fields from operation modules using the TypeScript compiler API for documentation artifacts.

## Goals / Non-Goals

**Goals:**

- Generate one `*.schema.ts` sidecar per registered operation handler
- Run codegen on `prebuild` and via standalone `npm run codegen:schemas`
- Sidecar exports `{handlerName}Schema` using `defineOperationSchema`
- Operation file imports sidecar — no manual field maps
- Share parser with templates generator
- Commit generated sidecars; fail build on parse errors

**Non-Goals:**

- Option A central registry
- Bundler plugin (ncc hook) in v1
- Parsing non-literal output types (aliases, imports)
- Auto-injecting schema without explicit import in operation module
- Merging templates and codegen CLI in v1

## Decisions

### D1: Sidecar naming and location

- **Choice:** `{module-basename}.schema.ts` next to `{module-basename}.ts` (e.g. `example-operation.schema.ts`)
- **Export name:** `{handlerExportName}Schema` (e.g. `exampleOperationSchema` from handler `exampleOperation`)
- **Reason:** Colocated; import path is obvious; matches Option B from design discussion

### D2: Codegen script

- **Choice:** `scripts/generate-operation-schemas.ts` with exported `generateOperationSchemas({ indexPath, operationsDir })`
- **Flow:**
  1. `parseRegistrations(indexPath)` → command + handler + module path
  2. `extractOperationSignature(modulePath)` → output fields
  3. Emit sidecar TS file per module
  4. Delete orphaned `*.schema.ts` files for removed operations (optional v1: warn only)

### D3: Emitted sidecar content

```typescript
/** AUTO-GENERATED by npm run codegen:schemas — do not edit manually */
import { defineOperationSchema } from '../framework'

export const exampleOperationSchema = defineOperationSchema({
    summary: 'string',
    step: { type: 'string', optional: true },
})
```

- **Choice:** Sort fields alphabetically for stable diffs
- **Banner:** Include generation command in header comment

### D4: prebuild integration

- **Choice:** `"prebuild": "npm run clean && npm run codegen:schemas"` (replace or extend current prebuild)
- **Reason:** Sidecars must exist before `ncc build`

### D5: Introspection sharing

- **Choice:** Codegen imports from `scripts/templates/operation-introspection.ts` directly
- **Alternative:** Move shared parser to `scripts/lib/operation-introspection.ts` — do if circular deps arise
- **Reason:** Minimize diff; templates and codegen stay aligned

### D6: Error handling

- **Choice:** Exit code 1 + stderr message when:
  - Registered handler module missing
  - No `OperationSignature` interface found
  - Zero output fields (warn) vs hard fail (TBD: warn for empty output)

### D7: Migration from manual schema

- **Choice:** Update `example-operation.ts` and `_template.ts` to import sidecar; remove inline `defineOperationSchema` blocks
- **Keep:** `defineOperationSchema` in framework for emission and rare manual overrides

## Risks / Trade-offs

- [Risk] Author edits interface, forgets rebuild → Mitigation: prebuild always regens; committed sidecar shows diff in PR
- [Risk] Parser lag behind TS features → Mitigation: document supported patterns; fail loudly
- [Trade-off] Committed generated files add noise → Accepted for review visibility

## Migration Plan
